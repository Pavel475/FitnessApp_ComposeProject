# Документ «Модель угроз v2, Планы атак (Red Team) и Защиты (Blue Team)» (PRO-уровень)

## 1. Model Diff (Версия v2: Сценарий изменения требований)

**Контекст изменения:** В приложение добавлена новая бизнес-фича: *«Облачная синхронизация профиля и P2P-обмен авторскими программами тренировок с друзьями»*.

### Изменения в модели угроз (Diff):

* **Активы (Assets):**
    * `+ A6`: Токен авторизации облачного сервиса (OAuth2 Bearer Token) — хранение в памяти и `EncryptedSharedPreferences`.
    * `+ A7`: Граф социальных связей и P2P-трафик обмена файлами тренировок.
* **Границы доверия (Trust Boundaries):**
    * `+ TB4`: Граница «Приложение <-> P2P-клиент стороннего пользователя» (доверие отсутствует).
* **Профили нарушителей:**
    * `+ P5`: Социальный фродер / Недобросовестный «друг» (цель: подмена показателей тренировок в общем рейтинге, кража авторских программ).
* **Поверхность атаки:**
    * `+ EP7`: Deep Links (`fitnessapp://share/workout?id=...`) для импорта программ тренировок.
    * `+ EP8`: WebSocket / P2P endpoint для передачи файлов тренировок в реальном времени.

## 2. Планы атак (Attack Plans / Red Team)

### Attack Plan #1: Внедрение вредоносной нагрузки через SAF JSON-отчет (DoS / Data Corruption)
* **Профиль нарушителя:** P1 (Скрипт-кидди / Массовый фродер — низкие возможности).
* **Предпосылки:** Жертва скачала сторонний `.json` файл отчета из недоверенного источника (Telegram-канал/форум) и выбрала его через SAF в `ProfileScreen`.
* **Шаги атаки:**
    1. Создать специально сформированный `fitness-report.json` с вложенным массивом из $10^6$ элементов или битой UTF-8 кодировкой.
    2. Распространить файл под видом «Программы тренировок от профессионального тренера».
    3. Жертва открывает `ProfileScreen` -> Нажимает «Импорт отчета» -> Выбирает файл через SAF `ACTION_OPEN_DOCUMENT`.
    4. Приложение пытается распарсить JSON в Main Thread или без ограничений памяти -> возникает `OutOfMemoryError` или Crash приложения.
* **Критерий успеха:** Постоянный краш приложения при запуске или порча файла `fitness_profile_report.json` во внутреннем хранилище.
* **Стоимость атаки:** 0 руб., ~15 минут (создание JSON-скрипта).
* **Точки детекции:**
    * Шаг 3: Валидация размера файла перед открытием `InputStream`.
    * Шаг 4: Перехват ошибок парсинга `kotlinx.serialization` в блоке `runCatching`.
* **Choke Point:** Валидатор `FitnessFileRepository.importFromUri()` до вызова `decodeFromString`.

---

### Attack Plan #2: Перехват и подмена сетевых данных тренировок (MITM / MockAPI Tampering)
* **Профиль нарушителя:** P3 (Сетевой атакующий — средние возможности).
* **Предпосылки:** Жертва подключена к публичной незащищенной сети Wi-Fi (например, в фитнес-клубе).
* **Шаги атаки:**
    1. Развернуть фейковую точку доступа Wi-Fi (Rogue AP) с перехватом DNS-запросов.
    2. Перехватить HTTP/HTTPS трафик к `mockapi.io`.
    3. Внедрить поддельный корневой CA-сертификат (если у пользователя ослаблена проверка ОС).
    4. Модифицировать JSON-ответ API: подменить длительность упражнений (`durationSeconds`) на аномальные значения ($36000$ сек).
    5. Приложение отображает искаженный план тренировки на экране `WorkoutPlayerScreen`.
* **Критерий успеха:** Пользователь получает некорректную программу тренировки, вызывающую сбой логики таймера.
* **Стоимость атаки:** ~$100 (Wi-Fi Pineapple) + 2 часа работы.
* **Точки детекции:**
    * Шаг 3: Срабатывание `Network Security Config` (Отказ от Cleartext + SSL Pinning).
    * Шаг 5: Валидация диапазонов в `WorkoutMapper.kt` (`durationSeconds.coerceIn(5, 3600)`).
* **Choke Point:** Отказ OkHttp-клиента устанавливать TLS-соединение при несовпадении пина сертификата (SSL Pinning).

---

### Attack Plan #3: Дамп памяти и извлечение локальных файлов на Root-устройстве (Local Data Extraction)
* **Профиль нарушителя:** P4 / P2 (Целевой атакующий / Вредоносный софт с Root-правами — высокие возможности).
* **Предпосылки:** На устройстве пользователя установлен Root (Magisk/SuperSU) и вредоносное ПО с правами суперпользователя.
* **Шаги атаки:**
    1. Вредоносное ПО запрашивает Root-права на устройстве.
    2. Получает доступ к файловой системе по пути `/data/data/com.example.fitnessapp_composeproject/files/`.
    3. Выполняет чтение локального файла `fitness_profile_report.json`.
    4. Эксфильтрует персональные данные атлета (вес, рост, история) на C2-сервер атакующего.
* **Критерий успеха:** ПДн пользователя полностью скомпрометированы без ведома самого пользователя.
* **Стоимость атаки:** Высокая (разработка 0-day для Android или целевой троян).
* **Точки детекции:** Детект наличия Root-прав / Frida в процессе приложения при запуске.
* **Choke Point:** Зашифрованный файл `EncryptedFile` (Jetpack Security) — даже при компрометации `/data/data/` файл представляет собой шифротекст.

## 3. Kill Chain и точки детекции (Detection Matrix)

| Стадия Kill Chain | Attack Plan #1 (SAF JSON) | Attack Plan #2 (MITM Network) | Attack Plan #3 (Root Memory Extraction) |
| ----- | ----- | ----- | ----- |
| **1. Reconnaissance** | Нет детекции (скачивание файла) | Нет детекции (сканирование Wi-Fi) | Нет детекции (анализ установленных APK) |
| **2. Weaponization** | Детект сигнатур на диске (Scan) | Подготовка фальшивого CA | Сборка root-скрипта Frida |
| **3. Delivery** | SAF File Picker Dialog (**Детект: MimeType/Extension**) | Rogue AP Connection (**Детект: Captive Portal**) | Установка софта (**Детект: Package Manager**) |
| **4. Exploitation** | Парсинг JSON (**Детект: Size Limit & Schema Validation**) | TLS Handshake (**Детект: Network Security Config Fail**) | Доступ к `/data/data/` (**Детект: Root Check / SafetyNet / Play Integrity**) |
| **5. Post-Exploitation** | Crash / DoS (**Детект: UncaughtExceptionHandler**) | Data Tampering (**Детект: Mapper Range Checks**) | Exfiltration (**Детект: Encrypted Storage Read Error**) |

## 4. План защиты (Blue Team Defense Plan)

### Архитектура эшелонированной защиты (Defense-in-Depth):

```
       [ Входящие данные (SAF / Network) ]
                       │
                       ▼
┌───────────────────────────────────────────────┐
│ 1. Предотвращение (Prevention)                │
│    - Size Limits (<= 5 MB)                    │
│    - Network Security Config (No Cleartext)   │
│    - EncryptedFile (MasterKey в KeyStore)     │
└──────────────────────┬────────────────────────┘
                       │
                       ▼
┌───────────────────────────────────────────────┐
│ 2. Обнаружение (Detection)                    │
│    - SafetyNet / Play Integrity API           │
│    - RASP (Root & Frida Detection)            │
│    - Try-Catch Exception Logging (SIEM)       │
└──────────────────────┬────────────────────────┘
                       │
                       ▼
┌───────────────────────────────────────────────┐
│ 3. Реакция (Incident Response)                │
│    - Откат к дефолтному состоянию профиля     │
│    - Блокировка сетевых запросов при Root     │
│    - Безопасное отображение Toast пользователю│
└───────────────────────────────────────────────┘
```

### Метрики эффективности защиты:
* **MTTD (Mean Time to Detect):** $< 100$ мс (для локальных аномалий SAF и сети).
* **MTTR (Mean Time to Respond):** Immediate (мгновенный откат состояния и вызов `Result.failure()`).
* **Target False Positive Rate:** $< 0.1\%$ (минимизация ложных срабатываний валидаторов).

## 5. Количественная оценка риска (ALE vs Cost of Countermeasures)

### Расчет ALE (Annual Loss Expectancy):
$$\text{ALE} = \text{SLE} \times \text{ARO}$$
где:
* **SLE (Single Loss Expectancy):** Ущерб от одного инцидента (компрометация ПДн 152-ФЗ, штрафы, репутация, уход пользователей).
* **ARO (Annual Rate of Occurrence):** Ожидаемое количество инцидентов в год.

### Сравнительный анализ для FitnessApp:

| Угроза / Сценарий | SLE (Оценка ущерба) | ARO (Частота в год) | ALE (Годовой риск) | Контрмера | Стоимость контрмеры (разработка + поддержка) | Чистая выгода (ALE - Cost) |
| ----- | ----- | ----- | ----- | ----- | ----- | ----- |
| **U1: DoS/Crash через SAF JSON** | 50 000 руб. (потеря лояльности) | 12 (1 раз в мес.) | **600 000 руб.** | Валидация схем, ограничение размера 5 МБ в `FitnessFileRepository` | ~15 000 руб. (0.5 инж.-дня) | **+ 585 000 руб.** (Выгодно) |
| **U2: MITM-перехват трафика** | 300 000 руб. (утечка токенов) | 2 (в публичных сети) | **600 000 руб.** | Network Security Config + SSL Pinning | ~30 000 руб. (1 инж.-день) | **+ 570 000 руб.** (Выгодно) |
| **U6: Утечка данных из `filesDir` при Root** | 1 500 000 руб. (штраф 152-ФЗ) | 0.2 (редкое событие) | **300 000 руб.** | Интеграция `EncryptedFile` (Jetpack Security) | ~45 000 руб. (1.5 инж.-дня) | **+ 255 000 руб.** (Выгодно) |
